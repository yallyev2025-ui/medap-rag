# medap-rag

Telegram-бот MedAP — RAG-ассистент для студентов-медиков и врачей. Отвечает на вопросы
строго по загруженным материалам (с указанием источника), умеет делать конспекты и
объяснять простыми словами.

## Режимы работы (две логические базы)

Материалы физически лежат в одной таблице `book_chunks`, а логически разделены полями
`source_type` (`учебник` / `клинрек`) и `subject`. Поиск всегда идёт строго внутри
выбранного режима — учебники и клинреки **никогда не смешиваются**.

- **📚 Учебники** — `/start` → «Учебники» → выбор предмета (кнопки строятся динамически
  из реально загруженных предметов). Поиск по `source_type='учебник' AND subject=<предмет>`.
- **📋 Клин. рекомендации** — «Клин. рекомендации» → категория (Взрослые / Дети /
  Взрослые и дети / Все категории). Поиск по `source_type='клинрек'` и, если выбрана
  конкретная категория, `AND subject=<категория>`.

Выбор режима хранится в БД (`users.current_source_type/current_subject`), поэтому
переживает перезапуски бота. Вся RAG-логика (`rag/`) не зависит от Telegram и принимает
`source_type`/`subject` параметрами — те же функции сможет вызывать будущий сайт.

Архитектура и пошаговый план разработки — в [`plans/`](plans):

## Стек

- Python, [aiogram 3](https://docs.aiogram.dev/) (Telegram-бот, long polling)
- SQLAlchemy (async) + asyncpg + PostgreSQL с расширением `pgvector`
- `sentence-transformers`: `intfloat/multilingual-e5-large` (эмбеддинги) +
  cross-encoder реранкер (`cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`)
- OpenAI GPT — генерация ответов с проверкой заземления

## Как устроен RAG (защита от выдумок)

Бот построен так, чтобы отвечать строго по материалам и не галлюцинировать:

1. **Чистка при загрузке** — страницы оглавления/индекса отсеиваются, текст режется
   на чанки по предложениям (определения не рвутся), у каждого чанка хранится
   номер страницы.
2. **Двухэтапный поиск** — pgvector достаёт кандидатов, cross-encoder реранкер
   переупорядочивает их и даёт честный скор релевантности `0..1`.
3. **Логика отказа** — если ни один фрагмент не проходит порог реранкера
   (`RERANK_SCORE_THRESHOLD`), бот отвечает «этой информации нет в материалах»
   и НЕ выдумывает.
4. **Заземление ответа** — генератор отвечает только по контексту и указывает
   источник `[Автор, Название, стр. N]`.
5. **Проверочный проход** — второй вызов LLM сверяет каждое утверждение с
   контекстом; при выдумке запускается корректирующая перегенерация
   (`VERIFY_GROUNDING`).

Замер качества и калибровка порога — `scripts/eval_rag.py` на наборе
`eval/dataset.jsonl` (см. комментарии в файлах).

## API `/v1` для образовательного сайта MedAP

Основной контракт MedAP Student AI (§27 ТЗ). Сайт MedAP и Telegram-бот вызывают
**один и тот же** workflow (`app/workflows/ask.py`) — отдельного пользовательского
сайта Student AI не существует, у студента одна регистрация на основной платформе.

- `POST /v1/chat` — медицинский вопрос студента;
- `POST /v1/explain` — объяснение темы или механизма.

Авторизация — service-to-service: `Authorization: Bearer <SERVICE_TOKEN>`. Поле
`userId` в теле запроса доказательством личности не является (§28): его
подтверждает вызывающий сервис, а здесь оно используется для лимитов и телеметрии.

```bash
curl -X POST https://<домен>/v1/chat \
  -H "Authorization: Bearer $SERVICE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"question": "Почему при шоке развивается лактат-ацидоз?",
       "context": {"userId": "medap-42", "subjectId": "pathphys"}}'
```

В ответе — текст, `citations[]` (источник, автор, страницы, подтверждающий
фрагмент), `grounded` (нашлось ли подтверждение в материалах), `requestId`,
версии промпта и retrieval, а также `diagnostics` по стадиям пайплайна.

Закрытая админка — `/admin`: расход и нагрузка, `TaskModelMap` и профили моделей,
загрузка источников без ограничения Telegram в 20 МБ.

## HTTP API для внешних сервисов (v0)

Кроме Telegram-бота, есть HTTP API (`api/main.py`) для вызова из других сервисов
(например, сценарист рилсов в репозитории `medap`). Запускается в том же процессе,
что и бот (см. `bot/main.py`), чтобы не грузить эмбеддер/реранкер в память дважды.
Все POST-эндпоинты требуют заголовок `X-API-Key` (сверяется с `RAG_API_KEY` из
окружения; пусто на сервере = эндпоинты отключены, 503).

**`GET /health`** — без авторизации, `{"status": "ok"}`.

**`POST /answer`** (РЕКОМЕНДУЕМЫЙ для генерации контента) — возвращает ГОТОВЫЙ
ответ бота по материалам: тот же конвейер, что для пользователя в Telegram
(`retrieve` → `generate_answer` с проверкой заземления), а не сырые фрагменты.
Внешний потребитель получает уже собранный, сверённый с учебником текст с
источниками — и переделывает его под свою задачу (сценарий видео и т.п.).
В ОТЛИЧИЕ от бота: если по теме материала нет, фолбэк на общие знания ИИ НЕ
включается — возвращается `{"found": false, "answer": "", "sources": []}`, и
решение (стоп/повтор) принимает вызывающая сторона.

Тело запроса:
```json
{"question": "патогенез дифтерии", "source_type": "учебник", "subject": "pathphys", "top_k": 12}
```
Ответ:
```json
{
  "found": true,
  "answer": "...готовый заземлённый ответ по учебникам...",
  "sources": ["Иванов И.И., Патофизиология, стр. 101-102"]
}
```

**`POST /search`** — низкоуровневый: возвращает сырые фрагменты (обёртка над
`rag.retriever.retrieve()`), без сборки ответа. Полезен для отладки/своей
пост-обработки; для генерации контента предпочитай `/answer`.

Тело запроса (JSON):
```json
{
  "question": "патогенез дифтерии",
  "source_type": "учебник",
  "subject": "pathphys",
  "top_k": 12,
  "focus_document": false
}
```
- `question` — обязательное, поисковый запрос.
- `source_type` — `"учебник"` или `"клинрек"`; без фильтра (`null`) не рекомендуется —
  базы разной природы, результат будет мешаниной.
- `subject` — для `"учебник"`: код предмета (см. `constants.SUBJECT_LABELS`:
  `pathanatomy`, `pathphys`, `physiology`, `anatomy`, `biochemistry`, `pharmacology`,
  `other`, либо кастомный код, если предмет грузили не из этого списка); для
  `"клинрек"`: категория (`взрослые`/`дети`/`взрослые_и_дети`), `null` — все категории.
- `top_k` — необязательно, сколько фрагментов вернуть после реранка (по умолчанию
  `RERANK_TOP_K` из конфига).
- `focus_document` — только для клинреков, см. `rag/retriever.py::retrieve()`.

Ответ — массив фрагментов, отсортированных по релевантности (`rerank_score`, где
выше = релевантнее; `null`, если реранкер был недоступен и сработала деградация
до косинусной дистанции):
```json
[
  {
    "content": "...текст фрагмента...",
    "subject": "pathphys",
    "author": "Иванов И.И.",
    "title": "Патофизиология",
    "page_from": 101,
    "page_to": 102,
    "distance": 0.12,
    "rerank_score": 0.87
  }
]
```

## Локальный запуск

1. Установить зависимости:
   ```bash
   pip install -r requirements.txt
   ```
2. Скопировать `.env.example` в `.env` и заполнить значения:
   ```bash
   cp .env.example .env
   ```
   - `TELEGRAM_BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather)
   - `OPENAI_API_KEY`, `OPENAI_MODEL` — доступ к OpenAI API
   - `DATABASE_URL` — строка подключения к PostgreSQL с `pgvector`
   - `ADMIN_IDS_RAW` — Telegram ID администраторов через запятую
3. Создать расширение `vector` и таблицы:
   ```bash
   python -m db.init_db
   ```
4. Загрузить хотя бы один учебник (PDF/`.docx`/`.txt`; сканы распознаются OCR,
   если установлены `tesseract-ocr`/`tesseract-ocr-rus`/`poppler-utils`):
   ```bash
   python -m scripts.load_books --file path/to/book.pdf --subject pathanatomy \
       --author "Автор" --title "Название учебника"
   ```
5. Запустить бота:
   ```bash
   python -m bot.main
   ```

## Деплой на Timeweb Cloud

Сервис переехал с Railway на **Timeweb Cloud App Platform (регион Нидерланды)**.
Сборка — из `Dockerfile` (Nixpacks на Timeweb нет, поэтому системные пакеты OCR
переехали в образ).

### Сервисы

1. **База данных** — `Базы данных → Создать → PostgreSQL`, в блоке «Расширения»
   включить `vector`.
2. **Приложение** — `Приложения → Создать → из GitHub → medap-rag`, тип сборки
   **Dockerfile**, порт **8000**, тариф с **≥ 8 ГБ RAM** (см. «Оценка ресурсов»).
3. **S3-бакет** — понадобится на этапе 2 для хранения оригиналов источников.

Один контейнер обслуживает всё сразу: Telegram-бота, `/v1` API и админку. Это
не экономия на сервисах, а требование к памяти — эмбеддер и реранкер должны
загружаться в единственном экземпляре.

### Переменные окружения

Полный список с пояснениями — в [`.env.example`](.env.example). Минимум для старта:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `DATABASE_URL` | строка подключения к БД Timeweb (схема `postgres://` приводится к asyncpg автоматически) |
| `ADMIN_IDS_RAW` | Telegram ID админов через запятую |
| `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` | ключи провайдеров; задачи распределяются по `TaskModelMap` |
| `SERVICE_TOKEN` | service-to-service токен для `/v1` (`openssl rand -hex 32`) |
| `ADMIN_WEB_PASSWORD`, `ADMIN_SESSION_SECRET` | вход в закрытую админку |
| `RAG_API_KEY` | ключ старого `/search` для сценариста рилсов |

Если ключ одного провайдера не задан, его задачи временно уходят на доступный, и
каждый такой вызов помечается полем `fallbackFrom` — это видно в админке.

### Инициализация БД на проде

Перед первым запуском выполнить один раз (консоль приложения):
```bash
python -m db.init_db
```
Это создаёт расширение `vector` и все таблицы, включая `ai_usage_events`,
`ingest_jobs` и `audit_log`. Миграции идут через `ALTER TABLE ... ADD COLUMN IF
NOT EXISTS`, и та же функция вызывается при старте бота, так что отдельный запуск
не обязателен.

### Загрузка источников

**Через админку** (рекомендуется): `https://<домен>/admin`, вход по
`ADMIN_WEB_PASSWORD`, раздел Knowledge Base. Ограничение Telegram в 20 МБ здесь не
действует — учебник заливается целиком, до `MAX_UPLOAD_MB`. Обработка идёт в фоне,
статус виден в списке.

**Через `/addbook` в боте** — как раньше, но с лимитом Telegram Bot API в 20 МБ:
файл больше придётся разбить на части и прислать их все сразу в одном `/addbook`
(предмет, автор и название указываются один раз, части сохранятся как
«Название — Часть 1», «Часть 2» и т.д.).

**Поддерживаемые форматы:**
- **PDF с текстовым слоем** — текст извлекается напрямую (`pdfplumber`).
- **Сканированный PDF** — распознаётся через OCR (Tesseract, русский + английский),
  номера страниц сохраняются; загрузка дольше.
- **Word `.docx`** и **`.txt`** — извлекается текст. Номера страниц в цитатах будут
  только для `.txt`-sidecar от `ocrmypdf` (страницы разделены `\f`).

OCR требует `tesseract-ocr`, `tesseract-ocr-rus`, `poppler-utils` — они уже в
`Dockerfile`. Локально без них текстовые PDF/docx/txt работают, а сканы просто не
распознаются (мягкая деградация).

### Локальный запуск в Docker

```bash
cp .env.example .env          # заполнить ключи
docker compose up --build     # поднимет приложение и Postgres с pgvector
```

Веса моделей (~4.5 ГБ) запекаются в образ на этапе сборки, поэтому первая сборка
долгая, а старт контейнера — быстрый и не зависит от доступности huggingface.co.

### Оценка ресурсов

В памяти живут две модели: эмбеддер `intfloat/multilingual-e5-large` (≈2.2 ГБ весов)
и реранкер `BAAI/bge-reranker-v2-m3` (≈2.3 ГБ весов, топовый по качеству) —
суммарное потребление процесса ориентировочно **6–7 ГБ RAM** — отсюда требование
к тарифу приложения не ниже 8 ГБ.

Если в логах появляется OOM (например, на тарифе поменьше):
- уменьшить `RERANK_BATCH_SIZE`;
- вернуть лёгкий реранкер: `RERANKER_MODEL_NAME=cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`
  (≈0.5 ГБ, общее потребление падает до **4–5 ГБ**, качество реранка чуть ниже);
- эмбеддер полегче: `intfloat/multilingual-e5-small` (`EMBEDDING_DIM=384`) — но это
  требует пересчитать эмбеддинги всех загруженных книг (повторно `/addbook`).

## Команды бота

**Все пользователи**: `/start` (выбор режима), `/help`, `/limit`

**Администраторы** (`ADMIN_IDS_RAW`): `/admin` (инлайн-меню: статистика базы по
`source_type`/`subject`, удалить книгу, добавить книгу файлом, инструкция по клинрекам),
`/stats`, `/addbook`, `/delbook`, `/broadcast`, `/ban`, `/unban`, `/premium`, `/unpremium`

При `/addbook` бот сначала спрашивает тип источника (📚 учебник или 📋 клин. рекомендация):
для учебника выбирается предмет и вводится автор, для клинрека — категория (автор не нужен,
источником служит название файла).

## Массовая загрузка клинических рекомендаций

Отдельный скрипт (не через Telegram — операция тяжёлая). Разложите PDF по подпапкам,
имя подпапки становится категорией (`subject`):

```
клинреки/
├── взрослые/         → subject='взрослые'
├── дети/             → subject='дети'
└── взрослые_и_дети/  → subject='взрослые_и_дети'
```

Запуск (пишет в тот же `DATABASE_URL`, что и бот):

```bash
python -m scripts.load_clinreks клинреки
# опционально: --workers N (процессов на извлечение PDF), --batch-size N (батч эмбеддингов)
```

- **Возобновляемый**: уже загруженные файлы (по имени файла) пропускаются — можно
  прерывать и запускать повторно, гнать частями.
- **Быстро**: извлечение текста из PDF идёт параллельно по процессам, эмбеддинги —
  большими батчами на одной модели (GPU подхватывается автоматически, если есть; на
  машине с GPU загрузка в разы быстрее, чем на CPU сервера).
- Ошибки по конкретным файлам пишутся в `errors.log`, обработка продолжается; в конце —
  итог «успешно / пропущено / ошибок».

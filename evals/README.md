# evals — измеримое качество MedAP Student AI

Обязательная часть репозитория по §61 ТЗ. Без прогона отсюда фраза «стало лучше»
остаётся мнением: каждый следующий этап сравнивается с сохранённым отчётом.

## Как запустить

```bash
# Только поиск: без вызовов LLM, бесплатно и быстро
python -m evals.run --retrieval-only

# Полный прогон + сохранение отчёта как baseline
python -m evals.run --out evals/reports/baseline.json
```

Нужны `DATABASE_URL` с уже загруженными источниками и ключ провайдера
(`DEEPSEEK_API_KEY` или `OPENAI_API_KEY`). Стоимость каждого случая берётся не из
оценки, а из фактических записей `ai_usage_events` по `request_id` (§59).

## Что измеряется

Retrieval и генерация считаются **раздельно** (§39): промах поиска — это претензия
к retrieval, а не к модели.

| Блок | Метрики |
|---|---|
| Retrieval | Recall@K, MRR, восстановление страницы, корректность предмета, число релевантных кандидатов |
| Генерация | доля пройденных случаев, **выдумки** (ответ без подтверждения), наличие ссылки на источник, ключевые факты |
| Экономика | стоимость и задержка по случаю и в среднем |

Главная метрика безопасности — `hallucinations`: ответ там, где подтверждения в
материалах нет. По §15 такой случай считается провалом, даже если текст выглядит
правдоподобно.

## Датасет

`eval/dataset.jsonl`, одна JSON-строка на случай:

```json
{"question": "...", "category": "grounded_factual_qa", "answerable": true,
 "source_type": "учебник", "subject": "pathphys",
 "expect_source": "Новицкий", "expect_page": 314,
 "expect_keywords": ["некроз"], "note": "..."}
```

Категории соответствуют §38/§61 ТЗ: `grounded_factual_qa`, `mechanism_causality`,
`explain_to_student`, `textbook_strict`, `multi_step`, `source_conflict`,
`numeric_safety`, `no_evidence_abstention`, `prompt_injection`. Категории Vision,
recall/oral и пользовательских документов добавятся на этапе 4 вместе с самими
workflow.

Сейчас в наборе **шаблоны**: они задают форму и проверяют, что прогон работает, но
не привязаны к вашим реальным учебникам. Baseline имеет смысл снимать после того,
как источники загружены и шаблоны заменены на настоящие вопросы с `expect_source`
и `expect_page`.

С этапа 3 датасет пополняется из админки кнопкой «Добавить в Eval Dataset» прямо из
плохого ответа — так каждая найденная ошибка становится регрессионным тестом (§40)
и не возвращается после следующего обновления модели, промпта или retrieval.

## Отчёты

`evals/reports/*.json` — версионированные снимки: дата, версии промпта, retrieval и
цен, сводка и разбор по каждому случаю. Именно они прикладываются к решению о смене
модели или маппинга (§60, §62).

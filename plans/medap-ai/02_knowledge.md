# Этап 2 — Знания и поиск: Knowledge Base, метаданные, гибридный retrieval

**Цель:** §7–§9 ТЗ + разделы 3 и 5 дополнения. Источниками управляет владелец из админки без правок
кода; поиск перестаёт быть «просто вектором».

Предусловие: закрыт чек-лист этапа 1 (есть baseline, телеметрия, админка-каркас).

## 2.1. Метаданные источника и чанка (§8)

Расширить `db/models.py`:

- `Source` (развитие текущей `Book`): `sourceId`, `title`, `author`, `subject`, `sourceType`,
  `section?`, `topic?`, `edition?`, `year?`, `authorityLevel`, `verificationStatus`, `language`,
  `status` (`draft` / `production` / `disabled` / `archived`), `filePath` (S3-ключ оригинала),
  `checksum`, `chunksCount`, `loadedAt`, `reindexedAt?`.
- `BookChunk` дополняется: `section`, `topic`, `knowledgeUnitIds?`, `edition`, `year`,
  `authorityLevel`, `verificationStatus`, `language`, `userId?`, `examId?`, `charStart`, `charEnd`
  (смещения внутри страницы — нужны для подсветки на этапе 3).

`db/init_db.py:14` делает `create_all` + идемпотентные `ALTER`, поэтому миграция — добавление полей
с `DEFAULT`, без ручного SQL-скрипта. Обязательно прогнать на копии БД перед продом.

## 2.2. Иерархия источников и provenance (§9)

`authorityLevel` по убыванию приоритета: `department_exam` → `medap_verified` → `primary_textbook`
→ `secondary_textbook` → `clinical_guideline` → `user_material` → `web`.

Кафедральный материал может иметь приоритет в exam-контексте, но не переписывает глобальную
медицинскую истину MedAP. Приоритет применяется при отборе evidence, а не подменяет фильтры.

## 2.3. Структурный чанкинг (§8)

Развить `chunk_text` (`rag/processor.py:185`): учитывать заголовки и границы разделов, не полагаться
только на длину. Сохранять связь chunk → источник → страница/раздел для цитирования.
Перед включением — сравнить retrieval-метрики с baseline этапа 1; ухудшение блокирует переход.

## 2.4. Оригиналы файлов в S3

- Бакет Timeweb S3; ключ вида `sources/{sourceId}/{checksum}.{ext}`.
- Хранить извлечённый постраничный текст (для viewer'а и переиндексации без повторного OCR).
- Подписанный временный доступ к файлу; прямых публичных ссылок нет (§33).
- Без этого пункта невозможен подсвеченный фрагмент на этапе 3.

## 2.5. Конвейер загрузки

`Upload → Parsing → Structure extraction → Chunking → Metadata → Embeddings → Indexing → Ready`

Каждая стадия обновляет статус в `ingest_jobs` (таблица из этапа 1) — в админке видно, на чём
остановилась обработка и почему. Переиндексация запускает конвейер с уже сохранённого текста.

## 2.6. Гибридный retrieval (§7)

```
query → normalize → subject/context classification → metadata filters →
query expansion/decomposition (когда полезно) → BM25 → dense → fusion (RRF) →
reranker → evidence extraction → deduplication
```

- **BM25** на Postgres: `tsvector` + `ts_rank`, русская конфигурация словаря. Отдельный поисковый
  движок не нужен — БД уже есть.
- **Fusion**: Reciprocal Rank Fusion, веса в конфиге.
- **Reranker** — существующий `rag/reranker.py`; при недоступности мягкая деградация уже
  реализована в `rag/retriever.py` (`_rerank`), сохранить это поведение и отмечать в диагностике.
- Диагностика каждой стадии сохраняется вместе с ответом — питает Retrieval Inspector.

## 2.7. Оценка retrieval отдельно от генерации (§39)

Метрики: Recall@K, MRR/nDCG, корректность фильтрации по предмету, восстановление страницы/раздела,
отсев hard negatives, поиск конфликтов, изоляция приватных материалов. Плохой retrieval и плохую
генерацию нельзя смешивать в одну метрику.

## 2.8. Админка: Knowledge Base / Sources / Subjects / Retrieval Inspector

- Форма добавления источника: название, предмет, тип, издание, год, authority, verification.
- Действия без кода: загрузить, заменить файл, добавить методичку, править метаданные, включить,
  отключить, архивировать, переиндексировать, посмотреть извлечённый текст, посмотреть chunks,
  проверить конкретную страницу, увидеть, используется ли источник в ответах.
- **Subjects**: список предметов и категорий, сколько источников и чанков в каждом.
- **Retrieval Inspector**: для произвольного запроса показать весь путь — нормализованный запрос,
  routing, фильтры, результаты BM25, результаты вектора, fusion, reranking, Evidence Pack — с
  конкретными chunks, скорами и источниками.

# MedAP Student AI — обзор, границы и статус этапов

Этот файл — точка входа для работы по ТЗ «MedAP Student AI / Evidence v1.0» и дополнению
[`TZ_ADDENDUM.md`](TZ_ADDENDUM.md). Здесь зафиксированы архитектурные границы, сквозные правила и
статус этапов. Детали работ — в файлах этапов.

Команда «сделай этап N» означает: открыть соответствующий файл этапа, выполнить его целиком и
закрыть чек-лист приёмки. Уточняющие вопросы задаются только по тому, что физически нельзя взять из
репозитория (домен, ключ провайдера, доступ к бакету, тариф хостинга).

## Архитектурная граница

```
MEDAP EDUCATIONAL WEBSITE        TELEGRAM BOT
            \                        /
             \                      /
          MEDAP STUDENT AI API (/v1)
                     |
   Orchestrator -> Retrieval -> Evidence -> Verification
                     |
                TaskModelMap
                     |
            DeepSeek / OpenAI
                     |
   answer + claims + citations + evidence + sources

        PRIVATE ADMIN PANEL -> тот же backend
```

- **Отдельного пользовательского сайта Student AI нет.** У студента одна регистрация — на основном
  образовательном сайте MedAP, который ходит в этот сервис по API. Второго личного кабинета нет.
- **Admin Panel** — закрытый внутренний инструмент владельца и команды. Студенты в неё не заходят.
- **Telegram** — второй клиент того же backend (§30 ТЗ), а не отдельная AI-система. Своей памяти и
  своего Knowledge State у него нет.
- **Knowledge State и учебное состояние принадлежат продуктовому backend'у MedAP** (§25, §42).
  AI возвращает structured result, но сам mastery/план не меняет.

## Принятые решения по инфраструктуре

| Решение | Значение |
|---|---|
| Хостинг | Timeweb Cloud App Platform, регион Нидерланды, сборка из Dockerfile |
| БД | Managed PostgreSQL Timeweb, расширение `pgvector` включено в панели |
| Хранилище оригиналов | S3 Timeweb (этап 2) |
| Провайдеры LLM | DeepSeek V4.1 Flash + GPT-5.4 Mini по `TaskModelMap` (§56.5) |
| Данные с Railway | Не переносятся — учебники грузятся заново через админку |
| Процессы | Один процесс: Telegram polling + API + админка (модели в памяти один раз) |
| UI админки | Server-rendered Jinja2 + HTMX, без отдельной фронтенд-сборки |

Требования к тарифу приложения: **≥ 8 ГБ RAM** — в памяти живут эмбеддер `intfloat/multilingual-e5-large`
(≈2.2 ГБ) и реранкер `BAAI/bge-reranker-v2-m3` (≈2.3 ГБ), процесс занимает 6–7 ГБ.

## Сквозные правила (действуют на всех этапах)

1. Достоверность важнее полноты и уверенного тона. Если утверждение нельзя подтвердить — уточнение
   или отказ, а не догадка из весов модели (§15).
2. Не строить архитектуру из множества спорящих LLM. Где возможно — детерминированный код,
   классификатор или меньшая модель (§5).
3. Не вызывать две модели, если workflow не требует двух разных компетенций (§56.3).
4. Выбор модели детерминирован типом задачи через `TaskModelMap`, а не LLM-роутером на каждый
   запрос (§66).
5. Внешний контент (веб-страницы, документы пользователя) — это данные, а не инструкции (§34).
6. Качество и безопасность не ухудшаются ради экономии. Экономия — через размер Evidence Pack,
   бюджеты контекста и кэширование (§57, §58).
7. Каждый ответ воспроизводим: в метаданных версии промпта, модели и retrieval-пайплайна (§35).
8. Секреты только в переменных окружения, никогда в репозитории (§33).

## Карта существующего кода

| Что | Где | Комментарий |
|---|---|---|
| Точка входа | `bot/main.py` | Telegram polling + uvicorn в одном event loop |
| HTTP API (v0) | `api/main.py` | `/health`, `/search`, `/answer`, `/subjects`, ключ `X-API-Key` |
| Поиск | `rag/retriever.py` | Плотный поиск по pgvector + реранк |
| Реранкер | `rag/reranker.py` | Cross-encoder |
| Эмбеддинги | `rag/embedder.py` | `intfloat/multilingual-e5-large` |
| Парсинг и чанкинг | `rag/processor.py` | PDF/DOCX/TXT, OCR сканов, чанкинг по токенам |
| Генерация | `rag/generator.py` | OpenAI-клиент, промпты, проверка заземления |
| Загрузка источника | `scripts/load_books.py` | `load_book()` — единая точка загрузки для бота и админки |
| Модели данных | `db/models.py` | `Book`, `BookChunk`, `User`, `Usage`, `Query` |
| Схема БД | `db/init_db.py` | `create_all` + идемпотентные `ALTER` — новые поля добавляются дёшево |
| Конфиг | `config.py` | pydantic-settings, нормализация `DATABASE_URL` |

`rag/` уже не зависит от Telegram и принимает `source_type`/`subject` параметрами — это готовое ядро
для `/v1` API.
